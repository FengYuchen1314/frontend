### 明确保留的已知问题

直接由 token A 替换为 token B、未触发 logout 时，全局 NiceModal 仍可能保留旧弹窗，其 `show()` Promise 也没有统一结算。现有 HeroUI 弹窗的提交归属保护不等于解决全局弹窗清理，旧业务弹层仍需统一审查。

`src/shared/_modals/nice-modal-session.regression.test.ts` 保留真实 NiceModal API 的失败复现：首次挂载前的待显示弹窗状态在会话替换后仍保留。它明确标为 `test.todo`、接入默认测试，不是通过项，也不是浏览器中已显示弹窗的实测。此次停止开发后没有落入半成品 SessionModalProvider 重构。后续修复需要覆盖旧弹窗结算、新会话同 ID 弹窗不被误删，以及快速退出/重开和 StrictMode。

另一个保留边界是复用同一 args 对象、在同一个未提交的 React 批次内连续 hide→show：当前 presentation 身份检测不能区分这两次调用。正常已提交的关闭→重开及传入新 args 的调用已有覆盖，极端同批次场景仍待修复。
